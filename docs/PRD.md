**Author:** aTenderLion

**Project Level:** 2
**Target Scale:** 量化交易教育和演示平台

## Goals and Background Context

### Goals

基于产品简介，我为这个 Level 2 项目定义以下核心目标：

- **教育价值目标**: 创建一个完整的AI辅助开发教程案例，展示GLM-4.6在量化交易项目中的应用
- **比赛成功目标**: 赢得GLM Coding大师赛，获得技术认可和社区关注
- **用户学习目标**: 让量化交易初学者在30分钟内理解单均线策略并能看到实际效果
- **技术展示目标**: 验证BMAD V6方法论在快速项目开发中的有效性
- **知识传播目标**: 推动量化交易技术在开发者社区的普及，降低学习门槛

### Background Context

量化交易作为金融科技的重要领域，对初学者而言存在显著的技术门槛。当前市场缺乏既具有教育价值又实用的学习工具，大多数专业平台功能过于复杂，不适合学习和演示。与此同时，GLM-4.6等AI模型在编程辅助方面展现出巨大潜力，但缺乏在金融科技领域的实际应用案例。

本项目瞄准这一市场空白，以中国期货市场为背景，选择简单易懂的单均线策略作为教学案例。通过GLM Coding大师赛的契机，我们将在2天内快速开发一个集教育、演示、实用于一体的Web平台，为不同水平的开发者提供从入门到高级的量化交易学习资源。

## Requirements

### Functional Requirements

基于产品简介的 MVP 功能，我定义以下功能需求：

- FR001: 系统必须能够通过 AKShare API 获取中国期货市场多个版块（能源、金属、农产品、化工）主流品种的历史数据
- FR002: 系统必须实现完整的单均线策略算法，包括自定义均线周期参数、开仓平仓逻辑和止损机制
- FR003: 系统必须提供精确的收益计算引擎，能够计算策略收益率、最大回撤、夏普比率等关键绩效指标
- FR004: 系统必须提供交互式数据可视化组件，展示价格走势、交易信号和策略收益曲线
- FR005: 系统必须提供响应式 Web 界面，支持桌面和移动端访问，适合不同水平用户使用
- FR006: 系统必须支持实时策略参数配置，允许用户调整均线周期并查看相应的回测效果
- FR007: 系统必须提供完整的历史数据回测功能，支持不同时间范围的策略分析和详细的交易记录
- FR008: 系统必须计算和展示风险指标，包括最大回撤、波动率和胜率，并提供风险等级评估
- FR009: 系统必须提供详细的使用教程和代码注释，帮助用户理解量化交易的基本概念和实现方法
- FR010: 系统必须支持一键部署到 GitHub Pages 或 Vercel，提供完整的项目使用说明
- FR011: 系统必须提供在线演示环境，用户无需本地安装即可快速体验所有核心功能
- FR012: 系统必须支持多品种对比分析，允许用户同时查看不同期货品种的策略表现

### Non-Functional Requirements

基于 Level 2 项目的规模和特点，我定义以下非功能需求：

- NFR001: 系统性能 - 页面加载时间必须小于 3 秒，策略回测响应时间必须小于 10 秒
- NFR002: 易用性 - 系统界面必须直观易用，量化交易初学者能在 30 分钟内独立完成策略分析
- NFR003: 可维护性 - 代码结构必须清晰模块化，包含详细注释，便于学习和后续开发

## User Journeys

**主要用户旅程：量化交易初学者学习路径**

**用户画像**: 小张，有基础编程概念但对量化交易感兴趣的开发者

**步骤 1: 首次访问和学习准备 (5分钟)**
- 通过推荐链接访问平台主页
- 观看简短的产品介绍视频（1分钟）
- 阅读项目概述和学习目标
- 选择感兴趣的期货品种（如原油期货）

**步骤 2: 理解单均线策略原理 (10分钟)**
- 查看策略原理的交互式教程
- 通过动画演示理解均线计算方法
- 学习开仓、平仓、止损的基本概念
- 查看示例数据和策略效果

**步骤 3: 参数实验和策略测试 (10分钟)**
- 使用默认参数运行策略回测
- 查看详细的交易记录和收益曲线
- 尝试调整均线周期参数（5日、10日、20日）
- 对比不同参数下的策略表现

**步骤 4: 结果分析和深入理解 (5分钟)**
- 查看风险指标（最大回撤、夏普比率等）
- 理解策略在不同市场环境下的表现
- 查看详细的代码实现和技术说明
- 下载分析结果或分享给朋友

**完成状态**: 小张在30分钟内完成了单均线策略的学习，理解了基本原理，能够独立运行策略分析，并对量化交易产生了进一步学习的兴趣。

## UX Design Principles

基于教育导向的项目定位和量化交易初学者的需求，我定义以下 UX 设计原则：

- **渐进式学习**: 界面设计应遵循"先易后难"的学习曲线，让用户能够从基础概念开始，逐步深入到复杂的策略分析
- **即时反馈**: 所有用户操作都应提供即时的视觉和数据反馈，帮助用户理解因果关系和策略效果
- **可视化优先**: 复杂的金融数据和策略逻辑通过图表、动画等可视化方式呈现，降低理解门槛
- **上下文帮助**: 在关键功能点提供嵌入式帮助和解释，无需用户离开当前页面即可获得所需信息
- **容错性设计**: 系统应对用户错误操作提供友好的错误提示和恢复机制，避免学习过程中的挫败感

## User Interface Design Goals

**平台和屏幕支持:**
- 主要目标平台：现代 Web 浏览器（Chrome、Firefox、Safari、Edge）
- 核心屏幕视图：主页、策略分析页面、结果展示页面、教程页面
- 导航方式：顶部导航栏 + 侧边栏功能导航
- 响应式设计：支持桌面端和移动端访问

**设计约束和要求:**
- 使用现代设计系统（如 Tailwind CSS）确保界面美观和专业性
- 色彩方案应体现金融科技的专业感，同时保持教育平台的友好性
- 图表和数据可视化需使用成熟的库（Chart.js/D3.js）确保性能和交互性
- 无需遵循特定品牌指南，但应保持设计的一致性和可访问性

## Out of Scope

基于产品简介和项目约束，以下是明确不包含在此项目中的功能：

**交易功能相关:**
- 实时交易功能和连接真实交易接口
- 模拟交易账户管理和资金跟踪
- 实时市场数据推送和价格预警
- 自动化交易执行和订单管理

**策略复杂度相关:**
- 多均线策略组合（双均线、三均线）
- 技术指标策略（RSI、MACD、布林带等）
- 机器学习和深度学习策略模型
- 高频交易和低延迟优化

**平台扩展相关:**
- 移动原生应用开发（iOS/Android）
- 用户账户和权限管理系统
- 社区功能和策略分享平台
- 付费功能和商业化运营

**数据和市场相关:**
- 从中国期货市场扩展到全球市场
- 从期货扩展到股票、期权、数字货币等
- 基本面分析和新闻数据集成
- 实时数据源的高级订阅服务

**技术基础设施相关:**
- 企业级数据库和高可用架构
- 微服务架构和容器化部署
- 高并发处理和负载均衡
- 企业级安全认证和合规要求

**明确的时间范围约束:**
- 项目必须在2天内完成开发和测试
- 11月10日前完成比赛提交，功能范围受时间限制

这些范围外的内容为后续版本的发展提供了明确的方向，但不会影响当前 MVP 的成功交付。
