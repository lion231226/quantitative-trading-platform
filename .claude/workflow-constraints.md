# Claude Code 工作流约束

## 核心原则

### 1. 严格遵守故事边界 🚫
- **绝对禁止**在故事范围外添加功能
- 只完成故事文档明确要求的验收标准
- "完成"不等于"完美"，足够好即可
- 任何改进想法必须通过正当渠道提出

### 2. 工作流程纪律 📋
1. **开始前确认**：当前应该开发哪个故事？
2. **阅读完整文档**：仔细理解验收标准和任务
3. **检查状态**：确认故事不是已完成状态
4. **严格按文档执行**：不多不少，精确完成
5. **完成后停止**：不主动添加未授权功能

### 3. 错误行为模式识别 ⚠️
必须避免以下思维模式：
- ❌ "这个功能可以更完善"
- ❌ "我可以添加一些额外的改进"
- ❌ "用户可能需要这个功能"
- ❌ "代码质量可以更好"
- ❌ 自作主张的技术优化
- ❌ 超出范围的架构改进

### 4. 正确的工作方式 ✅
- 🔍 **先询问**："当前应该开发哪个故事？"
- 📖 **再阅读**："完整理解故事要求"
- ✅ **然后执行**："严格按照文档开发"
- 🛑 **最后停止**："完成后立即停止"

## 纪律红线

### 禁止行为
1. **不确认故事就开始开发**
2. **超出故事文档要求**
3. **添加未授权功能**
4. **自作主张的"改进"**
5. **过度工程化**

### 必须行为
1. **每个功能都要有故事依据**
2. **每行代码都要文档支撑**
3. **每次修改都要用户授权**
4. **完成后立即停止工作**

- [ ] 只实现故事要求的组件

- [ ] 遇到疑问立即停止并询问

### 开发后检查
- [ ] 所有验收标准都已满足
- [ ] 没有超出范围的代码

## 心态调整

### 从 → 到
- 从"完美主义" → "足够好主义"
- 从"功能完善" → "需求满足"
- 从"技术展示" → "价值交付"
- 从"主动改进" → "精确执行"

### 核心心态
- **约束内创造价值**：在既定范围内做到最好
- **精确执行**：不多不少，刚好满足需求
- **边界意识**：清楚知道什么不能做
- **完成即止**：不做任何额外工作
